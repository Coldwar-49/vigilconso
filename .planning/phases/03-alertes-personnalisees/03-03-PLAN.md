```dart
if (_oneSignalAppId.isNotEmpty) {
  NotificationService.initialize(_oneSignalAppId);
  // ALRT-03: Foreground notification filter — suppress notifications that don't match subscriptions.
  // T-3-03: We never use URLs from notification additionalData — detail page links to official govt URL.
  // PITFALL-5: Read subscriptions inside the callback (not at registration) to avoid stale data.
  OneSignal.Notifications.addForegroundWillDisplayListener(
    (OSNotificationWillDisplayEvent event) async {
      final data = event.notification.additionalData;
      // No additionalData → display as-is (not a targeted recall notification)
      if (data == null) {
        event.notification.display();
        return;
      }
      final marque = (data['marque'] as String? ?? '').toLowerCase();
      final categorie = (data['categorie'] as String? ?? '').toLowerCase();
      // Read subscriptions at notification time (not at registration) — avoids stale data
      final brands = await SubscriptionService.getBrands();
      final categories = await SubscriptionService.getCategories();
      final matches = SubscriptionService.matchesSubscriptions(
        marque,
        categorie,
        brands,
        categories,
      );
      if (matches) {
        event.notification.display();
      } else {
        event.preventDefault();
      }
    },
  );
}
```

**Critical rules:**
1. Do NOT move the listener registration outside the `if (_oneSignalAppId.isNotEmpty)` block.
2. Do NOT call `SubscriptionService.getBrands()` at registration time — it must be inside the async callback.
3. Do NOT use `ref.read(subscriptionProvider)` — Riverpod container is not available in main() outside the widget tree.
4. The `event.notification.display()` call uses `event.notification`, NOT `event.notification.display()` with a URL from additionalData (T-3-03).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OneSignal notification additionalData → foreground filter | Untrusted notification payload (could be spoofed) used to match against user subscriptions |
| foreground filter → event.notification.display() | Decision to show or suppress notification based on untrusted additionalData |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-03 | Spoofing | Foreground listener reads additionalData['marque'] + additionalData['categorie'] | mitigate | additionalData is used ONLY for subscription matching (display/suppress decision). It is NEVER used as a URL or navigation target. RappelDetailsPage always opens official govt URL from the typed Rappel model (lienVersFicheRappel field). |
| T-3-01 | Tampering | matchesSubscriptions receives raw marque/categorie strings from notification | accept | matchesSubscriptions is a read-only filter — it only calls String.contains. No data is written based on notification payload. Risk accepted: injection via notification payload has no write effect. |
</threat_model>
