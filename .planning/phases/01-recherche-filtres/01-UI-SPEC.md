## Spacing Scale

Flutter spacing in logical pixels. Matches 8-point grid. All values extracted from existing codebase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge inner padding |
| sm | 8px | Between card sub-elements (brand/date row), inner chip padding |
| md | 16px | Horizontal screen padding, SearchBar horizontal padding |
| lg | 24px | Section separation in filter panel |
| xl | 32px | Not yet used in Phase 1 screens |
| 2xl | 48px | Not yet used in Phase 1 screens |
| 3xl | 64px | Not yet used in Phase 1 screens |

Exceptions:
- Card margin: 12px horizontal, 5px vertical (locked inherited value — pixel-perfect match to existing live code; do not normalize to grid; changing will break card density)
- Card internal padding: 12px all sides (existing pattern — preserved)
- Result counter bar: `fromLTRB(16, 4, 16, 4)` (existing pattern — preserved)
- Sort chip padding: 12px horizontal, 7px vertical (locked inherited value — pixel-perfect match to existing live code; do not normalize to grid)
- Touch targets for filter chips: minimum 44px height (accessibility — Material 3 default satisfies this)

Source: `lib/screens/rappel_screen.dart` — measured from existing card implementation

## Color

Design system: `ColorScheme.fromSeed(seedColor: Color(0xFFCC1421), brightness: Brightness.light/dark)`

Material 3 generates all tones from the seed. Executor MUST use `Theme.of(context).colorScheme.*` tokens — never hardcode derived colors.

| Role | Seed / Hex | ColorScheme Token | Usage |
|------|-----------|-------------------|-------|
| Dominant (60%) | System surface | `cs.surface` / `cs.surfaceContainerLow` | Screen background, list background |
| Secondary (30%) | System surface variants | `cs.surfaceContainerHighest`, `cs.primaryContainer` | Cards, filter panel background, image placeholder, shimmer |
| Accent (10%) | `#CC1421` (brand red) | `cs.primary` / `cs.onPrimary` | Reserved for specific elements only — see below |
| Destructive | `#B71C1C` | hardcoded (existing) | Risk "grave" indicator only |

**Accent (`cs.primary`) reserved for:**
1. "NOUVEAU" badge background
2. "NON LU" badge background (new — Phase 1 SRCH-07)
3. Active sort chip background
4. Active FilterChip selected state
5. Category label text above card title
6. Date label text inside card (calendar icon + date)
7. CTA buttons (ElevatedButton, FilledButton)
8. SearchBar focus ring / active state
9. Section title accent bar (4px left border)

**Accent NEVER used for:**
- Decorative backgrounds, shimmer base, inactive chips, general text

**Semantic risk colors (hardcoded — existing pattern preserved):**
| Risk Level | Color | Hex |
|------------|-------|-----|
| Grave / sérieux / élevé | Dark red | `Color(0xFFB71C1C)` |
| Modéré / moyen | Deep orange | `Color(0xFFE65100)` |
| Faible / bénin | Dark green | `Color(0xFF1B5E20)` |
| Unknown | Fallback | `cs.primary` |

**NON LU badge color:** `cs.primary` background, `cs.onPrimary` text (mirrors "NOUVEAU" badge pattern)

Source: `lib/main.dart` — theme definition; `lib/screens/rappel_screen.dart` — `_riskColor()`

## Component Inventory

New components introduced in Phase 1:

### 1. SearchScreen (`lib/screens/search_screen.dart`)

**Layout:** Scaffold with SearchBar at top + Overlay for suggestions + body alternating between history view and results ListView.

**States:**
- **Idle (< 2 chars typed):** Show search history list (max 10 items, `Icons.history`, tappable rows)
- **Suggesting (>= 2 chars, loading):** Show spinner row under SearchBar
- **Suggesting (>= 2 chars, loaded):** Show suggestions Overlay (max 8 items, `Icons.search` leading icon per row, brand name text)
- **Loading results:** Show shimmer list (6 cards, same shimmer as `_buildCardShimmer()`)
- **Results:** Show result count bar + sort chips + Google News card list
- **Empty:** Show empty state (see Copywriting)
- **Error:** Show error state (see Copywriting)

**SearchBar spec:**
- Widget: `SearchBar` (Material 3, Flutter 3.7+)
- Leading: `Icons.search`
- Trailing: `IconButton(Icons.clear)` when text non-empty + `IconButton(Icons.tune)` to open filter panel
- Hint: "Rechercher un produit, une marque..." (14px, `Colors.grey.shade500`)
- Debounce: 300ms on `onChanged` for suggestions trigger
- Trigger: `onSubmitted` for full search

### 2. FilterPanel (`lib/widgets/filter_panel.dart`)

**Presentation:** Bottom sheet (`showModalBottomSheet`) with `DraggableScrollableSheet`

**Layout within panel:**
```
[Handle indicator — 4px × 40px, centered, cs.outlineVariant]
[Title "Filtres" — 20px bold, 16px padding]
[Divider]
[Section "Niveau de risque" — 14px label]
  [FilterChip "Grave"] [FilterChip "Modéré"] [FilterChip "Faible"]
[Section "Période"]
  [FilterChip "7 jours"] [FilterChip "30 jours"] [FilterChip "90 jours"] [FilterChip "Personnalisé..."]
[Section "Marque / mot-clé"]
  [TextField — 14px, outlined, hint "Ex: Danone, Samsung"]
[Divider]
[Row: "Réinitialiser" (TextButton) | "Appliquer" (FilledButton, full width expanded)]
```

**FilterChip spec:**
- Widget: `FilterChip` (Material 3 built-in)
- Selected state: `cs.primary` background, `cs.onPrimary` text
- Unselected state: `cs.surfaceContainerHighest` background, `cs.onSurface` text
- Multiple selection allowed for risk level (AND logic client-side)
- Single selection for date presets (last selected wins; "Personnalisé" opens `showDateRangePicker`)

**Active filter indicator on list screen:**
- When filters active: Show `Wrap` of small `Chip` (deletable) below sort row showing each active filter
- Chip label: filter name (e.g., "Grave", "30 jours", "Danone")
- Chip trailing: `Icons.close` — tapping removes that filter and re-applies

### 3. Read/Unread Badge (`NON LU`)

**Position:** In card, same row as "NOUVEAU" badge (prepended, leftmost)
**Spec:**
```dart
Container(
  margin: const EdgeInsets.only(right: 6),
  padding: const EdgeInsets.symmetric(horizontal: 7, vertical: 2),
  decoration: BoxDecoration(
    color: cs.primary,
    borderRadius: BorderRadius.circular(20),
  ),
  child: Text('NON LU',
    style: TextStyle(color: cs.onPrimary, fontSize: 9,
      fontWeight: FontWeight.w800, letterSpacing: 0.5)),

```
- Font: 9px / w800 / uppercase / letterSpacing 0.5 (locked existing pattern — do not normalize to type scale)
- Badge disappears immediately when `onTap` fires (optimistic update, no round-trip wait)
- Badge is absent for read rappels (no "LU" badge — absence = read)

### 4. Sort Chips Row (existing — spec clarification)

Located above the list, right-aligned. Two chips only:

| Chip | Icon | Selected when |
|------|------|--------------|
| "Récent" | `Icons.arrow_downward` | `_isNewestFirst == true` (default) |
| "Ancien" | `Icons.arrow_upward` | `_isNewestFirst == false` |

No "Pertinence" chip — confirmed by RESEARCH.md (API has no relevance ranking). When in SearchScreen with a query, sort row still shows these two options only.

### 5. Search History List (idle state of SearchScreen)

- Title row: `Icons.history` + "Recherches récentes" (14px, `cs.onSurfaceVariant`)
- Per item: `ListTile`, leading `Icons.history` (`cs.onSurfaceVariant`), title = query string (15px), trailing `Icons.north_west` (fill icon, taps copy to field without submitting)

- Colored dot (8px diameter) + colored text label

### 7. Card Category Label

- Displayed above card title (libelle)
- Font: 11px / w700 / `cs.primary` color (locked existing pattern — do not normalize to type scale)

## Interaction Contracts

### SRCH-01: Search trigger
- HomeScreen existing search field submits → navigates to SearchScreen with initial query
- SearchScreen SearchBar `onSubmitted` → calls `RappelService.fetchRappels(categoryKey: 'all', searchQuery: query)` → results replace idle/suggestion state

### SRCH-02: Autocomplete timing
- `onChanged` with debounce 300ms → `_fetchSuggestions(prefix)` only when `value.length >= 2`
- Suggestions appear as Overlay positioned immediately below SearchBar
- Max 8 suggestions displayed
- Tapping a suggestion fills SearchBar and submits immediately (no second tap)
- Suggestions disappear on submit, on clear, or on focus loss

### SRCH-03: History behavior
- History shown when SearchBar is focused AND text length < 2
- Clicking a history item fills SearchBar AND submits (same as tapping suggestion)
- History updated after every successful submit (deduplication + LIFO, max 10)

### SRCH-04: Risk filter (client-side)
- Applied after results loaded into `_allResults`
- Multiple risk levels selectable simultaneously (OR logic: show if any selected level matches)
- Classification keywords: `['grave','sérieux','serieux','élevé','elevé']` → Grave; `['modéré','moyen']` → Modéré; `['faible','bénin','benin']` → Faible
- If filter active but no match: show empty state

### SRCH-05: Date filter
- Presets: 7j, 30j, 90j applied via `date_publication >= "YYYY-MM-DD"` API parameter
- "Personnalisé" opens `showDateRangePicker(locale: const Locale('fr', 'FR'), firstDate: DateTime(2020), lastDate: DateTime.now())`
- After selection, date chip shows formatted range "dd/MM – dd/MM"
- Presets mutually exclusive (last-selected wins)

### SRCH-06: Brand/keyword filter
- Client-side filter on `_allResults`, matches `marque_produit` field (case-insensitive `contains`)
- Applied in real-time as user types in filter panel TextField (no submit required within panel)

### SRCH-07: Read/unread toggle
- `onTap` on any card: immediately hide "NON LU" badge (optimistic), then call `ReadStatusService.markAsRead(id)` async
- ID resolution: `reference_fiche ?? libelle ?? numero_fiche`
- On list rebuild (e.g., return from details), read status re-checked from `ReadStatusService.isRead(id)`
- No "mark as unread" action in Phase 1

### SRCH-08: Sort toggle
- Sort chips are mutually exclusive toggle — tapping the already-selected chip does nothing
- Sort applied to `_allResults` in memory (no new API call)
- Default: "Récent" selected on screen open

### Navigation to SearchScreen
- Entry point 1: HomeScreen search field `onSubmitted` → `Navigator.push(SearchScreen(initialQuery: q))`
- Entry point 2: SearchBar `Icons.search` icon in AppBar of `RappelListScreen` (optional — if implemented)
- Back: standard Android back / iOS swipe — returns to HomeScreen

## Animation Contract

Preserve existing stagger animation on card list appearance:

```
AnimationController duration: 600ms
Per card:
  - delay = (index * 0.05).clamp(0.0, 0.7)
  - FadeTransition: 0.0 → 1.0
  - SlideTransition: Offset(0, 0.08) → Offset.zero
  - Curve: Curves.easeOut
```

Apply same animation to:
- SearchScreen results list (after query submit)
- FilterPanel-filtered results (after apply)

Shimmer animation: existing pattern from `_buildCardShimmer()` and `_AlertCardShimmer` — use same `primaryContainer.withValues(alpha: _anim.value)` + 1200ms repeat(reverse: true).

## Accessibility Contract

- All tappable elements: minimum 44px height touch target (Material 3 default satisfies chips/buttons)
- NON LU badge: do not rely on color alone — uppercase text label provides semantic meaning
- Risk indicator: colored dot (8px) + colored text — text provides semantic meaning alongside color
- `Semantics` label on card: `"${title}, ${brand}, ${timeLabel}, ${isRead ? '' : 'non lu'}"` — executor to add SemanticsLabel to InkWell
- Filter panel: accessible via bottom sheet (platform default focus management)
- SearchBar: platform keyboard `TextInputAction.search` — existing, confirmed in codebase
